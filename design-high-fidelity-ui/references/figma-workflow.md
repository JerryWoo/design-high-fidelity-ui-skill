# Figma 高保真工作流

## 目录

1. 保护文件
2. 使用稳定合同构建
3. 图片与字体
4. 原型交互
5. 回读验证
6. 截图失败恢复

## 1. 保护文件

- 写入前检查当前页面、文件名、视口、顶层节点和已有 Section。
- 保留之前的设计。除非用户明确要求替换，否则创建名称清晰的新 Section 或版本。
- 使用确定的间距，把新 Section 放置在已有顶层节点之后。
- 构建前搜索目标 Section 名称，防止意外重复生成。

## 2. 使用稳定合同构建

- 使用代码或其他机器可验证合同定义页面名称、宽度、高度、必需素材、必需文案和交互热区尺寸。
- 固定移动端画板使用明确的位置和尺寸。
- 使用能够表达归属和用途的图层名称，例如 `Home / Time Scroll / Panorama`。
- 使用统一辅助函数处理颜色、渐变、效果、文字、图标、图片和交互。
- 明确设置填充、描边、圆角、效果、字体属性和透明度，不得依赖 Figma 新建节点的默认值。
- 新建空 Frame 可能带有白色填充。不可见热区必须设置一个可见的 `SOLID` 填充，并把画笔透明度设为 `0`，随后通过回读确认。

## 3. 图片与字体

- 从经过验证的本地字节导入一次位图，并在多个页面复用。
- 场景背景使用 `FILL`，透明角色或产品使用 `FIT`。
- 使用 `search_nodes` 验证有名称的素材节点。导入图片通常表现为带有 `IMAGE` 填充的 `RECTANGLE` 节点，而不是类型为 `IMAGE` 的节点。
- 确认素材节点的可见性、透明度、尺寸、缩放模式和效果。
- 明确设置目标字体系列、字重、字号、行高、字间距和自动调整方式。
- 目标字体不可用时使用已经安装的备用字体，但必须保留衬线/无衬线角色和字重层级。
- 扫描所有文本节点，拒绝空文案、替换字符、乱码、截断和意外字体降级。

## 4. 原型交互

- 可见目标过小或视觉结构复杂时，使用独立热区图层。
- 所有热区至少为 44×44 像素。
- 常规导航使用 150–300 毫秒的淡入淡出转场。
- 只有具有空间或场景意义的转场才使用约 400–500 毫秒的 Smart Animate。
- 详情页需要返回导航历史时使用 `BACK`。
- 插件或网络响应较慢时，使用更长的 MCP 超时时间写入交互。

## 5. 回读验证

写入后直接回读以下内容：

- 当前页面和文件元数据。
- 主 Frame 名称和准确尺寸。
- 文本节点数量、内容和字体系列。
- 交互目标名称、尺寸、填充和透明度。
- 交互、目标节点 ID、转场类型和持续时间。
- 有名称的图片节点及其 `IMAGE` 填充、可见性、缩放模式和效果。

以 Figma 返回的规范化数据为准。持续时间可能返回 `0.479999989` 之类的浮点近似值，应使用容差比较；默认缓动字段可能不会出现在回读结果中。

## 6. 截图失败恢复

先逐个导出主要 Frame，再导出大型 Section。依次尝试 PNG 2 倍、PNG 1 倍、自动适配或合适情况下的 JPG。

如果 `get_screenshot` 反复超时：

1. 确认插件已经连接且中继服务健康。
2. 每次只重试一个节点。
3. 通过直接节点回读验证当前填充、可见性、文字、素材和交互。
4. 可用时，通过独立的 computer-use 机制捕获 Figma 应用窗口。
5. 不得使用较早导出的 PNG 证明当前设计状态。

必须区分截图导出失败与设计失败。即使当前 Figma 节点已经正确，旧 PNG 仍可能显示之前的遮挡层；应使用当前节点属性和独立捕获证明两者的区别。
