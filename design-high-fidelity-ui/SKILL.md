# 高保真 UI 设计

产出具有明确设计意图、功能完整、符合业务领域且可供真实用户使用的界面。把视觉质量、交互质量和验证质量视为同一个交付合同。

## 强制工作流

1. 选择视觉风格前，先检查产品背景、现有设计系统、技术栈、参考资料和当前渲染状态。
2. 提炼明确的验收合同：目标用户、视口、必需页面、内容层级、品牌信号、交互、素材和验证证据。
3. 开始构建前先定义精简的设计系统：颜色角色、字体层级、间距节奏、圆角、边框、层级阴影、图标体系、动效和组件状态。
4. 优先构建真正的核心使用体验。不得用营销落地页、功能说明或装饰外壳替代用户要求的 APP 或工具。
5. 使用能够清晰呈现主体的真实素材或生成素材。用户需要查看真实产品、地点、角色或状态时，不得留下空白媒体区、灰色占位块或仅有氛围的图片。
6. 完整实现控件、状态、导航、触控区域、文本换行、安全区和响应式约束。
7. 按真实目标视口渲染或捕获所有重要页面，与参考资料和验收合同进行比较，修复可见差异后再次检查。
8. 执行结构和行为验证。只有当前证据能够证明交付状态时，才能宣称完成。

设计或审查任何界面前，读取 [references/quality-standard.md](references/quality-standard.md)。

任务涉及创建或编辑 Figma 时，还必须在操作文件前读取 [references/figma-workflow.md](references/figma-workflow.md)。

## 参考图可编辑复刻

当用户要求“完全还原参考图”，同时要求按钮、图标、文字、配图和卡片可单独修改时，参考图是验收证据，不是可见交付层。禁止可见的整页截图充当最终界面；允许保留一张完整参考图，但必须隐藏并锁定，只用于校准和比较。

### 1. 锁定复刻合同

构建前记录准确视口、源文件路径和校验值、模块坐标、必需文案、素材裁切表、交互区域和图层命名。合同至少能够回答：

- 哪些元素必须是 `IMAGE` 独立位图，哪些必须是 `TEXT` 原生文字，哪些必须是 `FRAME`、矩形、椭圆或矢量节点。
- 每张独立素材的文件名、裁切范围、目标尺寸和缩放模式。
- 每段可见文案及其语义化节点名称。
- 哪些节点是交互目标；触控目标至少为 44×44 设计像素。
- 哪些旧 Section 或页面必须保留，目标 Section 如何避免重复生成。

用纯数据蓝图或测试固定这些合同。至少验证：视口、文案、素材、图层命名、图片数量、禁止整页可见图片和最小触控尺寸。

### 2. 按编辑需求拆层

- 文字、卡片、按钮、标签、边框、阴影、时间轴、状态标记和图标使用 Figma 原生节点重建。
- 人物、山水、商品、复杂云纹和照片质感插画裁成独立位图；每个主体单独导入并命名，不能把多个需要分别编辑的主体烘焙进同一张大图。
- 素材裁切不可避免地带有标签、角标或按钮时，先用匹配的可编辑表面覆盖烘焙文字和旧控件，再在上方重绘独立文字、徽标和图标。
- 场景图通常使用 `FILL`，透明角色或产品根据边缘和留白选择 `FIT` 或 `FILL`；导入前检查尺寸、四角、裁切边界和清晰度。
- 为素材生成联系表或等效预览，一次检查所有裁片是否误带相邻文案、按钮或卡片边框。

### 3. 原生节点构建

先创建新的 Section、准确尺寸的主 Frame 和语义化模块容器，再按蓝图顺序写入节点。明确设置填充、描边、圆角、阴影、字体、字号、行高、字间距和可见性，不依赖 Figma 默认值。

- 所有图片字节只加载一次，并在需要的位置复用。
- 所有节点使用“模块 / 元素 / 状态”格式命名；不得留下 `Frame 1`、`Rectangle 42`、`Text`、`Vector` 等默认图层名。
- SVG 导入后递归检查内部路径，并按所属图标语义化重命名，例如 `Header / Scan / Path 1`。
- 重复卡片可以由辅助函数生成，但图片、标题、价格、按钮背景、按钮图标和文案必须保持为独立子节点。
- 完整参考层放在主 Frame 中，尺寸与视口一致，写入后立即设为不可见并锁定。

### 4. 结构与视觉双验收

写入完成后必须节点回读，不能只看构建脚本的成功输出。检查：

- 主 Frame 名称和精确尺寸。
- 参考层存在、隐藏并锁定。
- 所有必需文本均为可编辑文字，且没有乱码、空文案或意外换行。
- 所有命名素材均具有 `IMAGE` 填充、正确尺寸、可见性和缩放模式。
- 不存在可见的整页图片，不存在默认图层名，所有交互目标尺寸合格。

随后按准确视口捕获当前 Figma Frame，与参考图并排做视觉对比。优先修复面积最大、最影响第一印象的差异：整体比例、主视觉裁切、模块高度、卡片边界、文字层级、按钮位置和底部导航。每轮修改后重新回读并重新截图，直到结构检查和视觉对比同时通过。

若截图导出失败，至少使用“节点回读 + Figma 应用窗口捕获”两种独立证据。Figwright 连接不稳定时，先启动 MCP 中继或保持进程，再重启插件，并轮询实际连接状态；不要依赖固定等待时间或旧截图判断结果。

以下情况必须返工：

- 视觉上接近参考图，但实际只铺了一张整页图片。
- 裁片仍显示烘焙标签，编辑上层文字后出现重影。
- SVG 图标根节点有名称，但内部路径仍全部叫 `Vector`。
- 测试通过，却没有捕获当前 Frame 做视觉对比。
- 页面可编辑，但拆层过碎、命名混乱，用户无法快速定位并二次修改。

## 设计决策

- 产品已经存在设计语言时，延续现有体系。仅在用户明确要求或当前产品没有统一体系时引入新的视觉方向。
- 让构图匹配业务领域。运营工具应紧凑、克制、便于扫描；消费和文化类产品可以更具表现力并以图像为主导。
- 使用克制且语义清晰的配色体系，避免界面被同一色相的近似颜色完全占据。
- 表现力强的展示字体必须搭配易读的正文字体。除非既有品牌规范另有要求，字间距保持为 0。
- 使用统一的图标体系，并为工具操作采用熟悉的符号。陌生的纯图标控件必须提供工具提示。
- 当体验依赖地点、物体、角色、产品或沉浸式场景时，优先使用全出血或无容器框的主视觉媒体。
- 卡片只用于确实需要分组或重复展示的内容。不得在卡片中嵌套卡片，也不得把每个页面区块都做成悬浮卡片。
- 动效必须服务于交互目的，常规动效保持在 150–300 毫秒；只有具有空间意义或场景意义的转场才使用更长时间。

## 交付门槛

不能因为页面使用了渐变、阴影或图片就称其为高保真。还必须同时满足以下条件：

- 必需内容和工作流完整存在。
- 文本清晰可读、正确换行，且不会与相邻内容重叠。
- 每个交互目标至少为 44×44 个 CSS 像素或设计像素。
- 动态内容不会导致固定格式控件位移或破坏布局。
- 主操作和次操作具有清晰的视觉区分。
- 在用户自然会期待的地方提供空状态、加载、错误、禁用、选中和按下状态。
- 根据任务需要，在目标移动端和桌面端尺寸进行视觉检查。
- 素材能够加载并正常渲染，截图或等效的当前状态证据不得为空白。
- 导航和原型交互必须回读或实际执行验证，不能只完成写入。
- 除非用户明确要求替换，否则保留用户已有工作。

无法直接获取截图时，至少收集两种相互独立的当前状态证据，例如浏览器渲染截图加 DOM 检查，或 Figma 节点回读加应用窗口捕获。必须说明仍然存在的验证限制，不能把旧截图当作当前结果。
